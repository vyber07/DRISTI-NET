## 1. Real role model

### 1.1 Backend roles (`models.py:16`)
`INVESTIGATOR`, `EVIDENCE_OFFICER`, `REVIEWER`, `ANALYST`, `AUDITOR`, `ADMIN`.

Authorization happens in two layers (`auth.py`):
1. **`require_roles(*roles)`**: a role allow-list. **ADMIN always passes** (`auth.py:63`). A denial is audited as `ACCESS_DENIED` / `ROUTE` and returns a 403 with the detail "Role X may not perform this action".
2. **`authorize_case(db, user, case_id)`**: ADMIN and AUDITOR may open any case. Every other role must be assigned to the case (or own it) **and** have the same jurisdiction as the case. A denial is audited with its reason and returns the neutral 403 "Access to this case is denied for the current user, purpose, or jurisdiction". A case that does not exist also returns 403, so the response never reveals whether the case exists.
3. Four checks are written inline in the route rather than through those helpers:
   - the reveal routes (`graph_routes.py:227`, `evidence_routes.py:175`) allow `INVESTIGATOR`, `REVIEWER` and `ADMIN`;
   - case assignment (`case_routes.py:59`) requires the case owner or ADMIN;
   - case creation (`case_routes.py:37`) requires a matching jurisdiction unless the user is ADMIN;
   - raw download (`evidence_routes.py:224`) returns 409 while the item is in quarantine, unless the user is ADMIN.
