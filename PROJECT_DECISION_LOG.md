| Decision ID | Date | Area | Decision | Rationale | Alternatives Considered |
|---|---|---|---|---|---|
| **DEC-001** | 2026-11-01 | Governance | Adopt `docs/context.md` as non-negotiable project constitution. | Establishes immutable boundaries, neutral language rules, and prevents status inflation. | Free-form development roadmap (rejected). |
| **DEC-002** | 2026-11-01 | Architecture | Preserve PostgreSQL + MinIO/S3 as authoritative stores; Neo4j as reconstructible projection. | Guarantees analytical flexibility without risking data loss if graph store is rebuilt. | Dual-authoritative model (rejected as prone to split-brain). |
| **DEC-003** | 2026-11-01 | Verification | Reconstruct 32-phase canonical roadmap combining Phases 0-22 with Phases 23-31. | Preserves historical continuity (Export 11, commit `0310914`) while incorporating recent additions (Kafka, Besu, NLP). | Inventing an entirely new roadmap (strictly prohibited by directive). |
| **DEC-004** | 2026-11-01 | Tooling | Standardize on `.venv311` (Python 3.11.14) and Node 24.22.0. | Contains full runtime requirements including PyTorch, PaddleOCR, Transformers, and Playwright. | System python without dependencies (incompatible). |
| **DEC-005** | 2026-11-01 | Testing | Fix frontend TypeScript build check from `tsc --noEmit` to `tsc -b --noEmit`. | References-only `tsconfig.json` bypasses checks in non-build mode, masking syntax errors. | Merging all tsconfig files into one (disrupts project references architecture). |
| **DEC-006** | 2026-11-01 | Language | Reconcile UI copy to strictly neutral terminology per Constitution §16. | Avoids illegal claims of court certification, admissibility guarantees, or automated guilt. | Retaining legacy "court-ready" marketing labels (rejected). |
| **DEC-007** | 2026-11-01 | API compatibility | Neutralise user-visible "court" wording but keep the route `/cases/{id}/report/court-pdf` and audit action `COURT_PDF_EXPORT`. | Renaming would break API clients and make historical audit queries inconsistent; identifiers are not user-facing claims. | Renaming the route and audit action (deferred; needs a versioned API change and an audit-action alias). |
| **DEC-008** | 2026-11-01 | Evidence states | Do not invent a backend→tier mapping for the frontend six-tier model (DEF-020). | Tier semantics define what "validated" means, which is a STRICT evidence-state decision for Roles 1/5 (constitution §15.2). The model is documented as internal governance only. | Deriving tiers from claim count/confidence in the UI (rejected: silent semantic invention). |
| **DEC-009** | 2026-11-01 | Graph UI | Graph filters fail open: they hide only types the user explicitly deselects, and unknown backend types are shown. | A vocabulary drift hid 117/117 edges silently (DEF-022); a failure that over-shows data the user is already authorised to see is safer than one that hides evidence. | Fail-closed filtering (the cause of DEF-022). |
| **DEC-010** | 2026-11-01 | Verification env | Live-store verification used disposable containers on 127.0.0.1 (postgres:16, neo4j:5-community, `bitnamilegacy/minio@sha256:451fe685…` 2025.5.24 as the S3 stand-in) and an isolated API on :8001 with a copied store. The public demo on :8000/:80 was not restarted or written to. | The pinned MinIO image is unobtainable (BLK-04); the :8000 instance is publicly proxied by host nginx. | Restarting the public demo; using `/demo/*` on the live DB. |
| **DEC-011** | 2026-11-01 | Evidence states | A stored evidence object that has disappeared is recorded as `INTEGRITY_MISMATCH` (error "stored object missing"), audited, and blocks reads with 409. | §6.1 treats hash mismatch this way; a missing object cannot match its manifest. No new state added to the shared vocabulary. S3 "missing" means 404 only, so a credentials error is never mistaken for loss. | DEF-042 |
| **DEC-012** | 2026-11-01 | Graph | Centered (hop-bounded) graph traversals are computed in-process from the authoritative projection on every backend; Neo4j serves the uncentered listing only when its ids agree with the authoritative rows, otherwise the response is marked `projection_stale`. | The Cypher traversal skipped the supernode cap (DEF-071) and a shared/out-of-date Neo4j returned foreign ids (DEF-072). The authoritative projection is already built per request, so this costs no extra query and keeps both backends' bounds identical. Neo4j remains a rebuildable projection (context §7.3). | DEF-071, DEF-072 |
| **DEC-013** | 2026-11-03 | Integrity | New Merkle anchors use RFC 6962 (0x00 leaf / 0x01 node prefixes, split at largest power of two); the construction is recorded per anchor (`merkle_scheme`) so legacy anchors keep verifying. | The legacy construction allowed second-preimage-style ambiguity (DEF-085). Roots cannot be recomputed under a new scheme, so the scheme must be stored, not inferred. | DEF-085 |
| **DEC-014** | 2026-11-03 | Identity | Source-file `person_id` values are scoped to the case (`pid:<case_id>:<id>`). Across cases, people are linked only through shared identifiers (phones, accounts) and human review. | A person_id is local to the source that issued it; a global key merged different people automatically (DEF-090, context §2.2/§11.2). | DEF-090 |
| **DEC-015** | 2026-11-04 | Access policy | Raw evidence download is restricted to the roles that may reveal masked values (INVESTIGATOR, REVIEWER, ADMIN) and requires an audited reason; it is a POST so the reason is not in URLs. | Decided by the project owner (asked 2026-11-04). Closes the masking bypass found in review. | DEF-101 |
