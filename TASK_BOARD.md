- [x] **Parser resource caps** (the other half of this line item): `config.CSV_MAX_ROWS` (existing

      `config.JSON_MAX_RECORDS` (20k default), `config.PDF_MAX_PAGES` (500 default) — all enforced in
      `validate_upload()`, so an oversized file is rejected with a clear 422 before it ever reaches
      quarantine, not discovered mid-extraction. A wall-clock/CPU timeout around the extractor itself
      was considered and explicitly rejected: `signal.alarm` only works reliably in a process's main
      thread, and extraction runs inline in the request-handling thread here — an alarm-based timeout
      would either silently do nothing (wrong thread) or risk interrupting unrelated code. An input-size
      cap gives a portable, deterministic bound on a single file's cost without that risk; a real
      queueing/worker architecture (already an Architecture target in `docs/architecture.md`) is the
      correct place for a true CPU/wall-clock timeout, not a signal hack bolted onto an inline call —

## Phase 14 — Graph query pagination (2026-09-12); cancellation recorded as blocked

Closes the remaining half of Role 5's backlog item (§10.4 "maximum hops; maximum nodes and edges" —
pagination lets a client actually reach nodes beyond one bounded page instead of only ever seeing the
same server-capped slice). Query *cancellation* was evaluated and is **not** implemented this phase —
see the blocker write-up below and the note appended to `task.md`, per directive §2/§56 (report the

- [x] `services/neo4j_store.py::read_bounded` gains an `offset` parameter: the uncentered ("no `center`")
      node listing now runs `ORDER BY n.entity_id SKIP $offset LIMIT $max_nodes` (the `ORDER BY` makes
      paging stable across requests — Cypher gives no ordering guarantee otherwise); `truncated` becomes
      `offset + len(node_ids) < total`. A **centered** hop-bounded traversal is deliberately left alone:
      a BFS neighbourhood has no natural total order to page through, so `offset` is accepted (never a
      surprise 422) but documented as having no effect once `center` is set — the same "don't fake it"
      posture as every other honestly-scoped limitation in this codebase.
- [x] `services/graph.py::bounded_subgraph` threads `offset` through to `read_bounded` for the real-Neo4j
      path, and slices the degree-sorted candidate list (`ranked[offset:offset+max_nodes]`) for the
      in-process fallback — same centered/uncentered scope split.
- [x] `routes/graph_routes.py::graph` accepts `offset` (422 on negative), returns `offset` and
      `next_offset` (null once there's nothing further to page to) in the response body.
- [x] `GraphView.tsx`: "load next page →" / "first page" controls (uncentered view only), a page-range
      indicator in the status row, and filter changes (centre/hops/max nodes/time window/candidates) now
      reset back to the first page via a shared `setFilter` wrapper instead of leaving a stale offset from
      a now-different view. `tsc -b && vite build` succeeds.
- [x] Tests: `test_workflow.py::test_graph_pagination_pages_through_the_full_uncentered_node_listing`
      (pages a 10-node-per-page listing through the whole seeded case with no gaps or duplicate nodes
      across pages, terminates at `next_offset: null`, and the union of all pages equals the unbounded
      listing; also asserts a centered view ignores `offset` rather than misbehaving) and
      `test_graph_pagination_rejects_negative_offset`. Full backend suite: 56/56 passing + 2 live-only
      skipped (was 54/54 before this phase). `ruff check` diffed against a `git stash` baseline for every
      changed file — identical pre-existing findings, zero new ones.
- [ ] **Cancellation — BLOCKED, not implemented.** Blocker (full detail appended to `task.md`): this
      project's graph queries run synchronously in the request thread by deliberate design (no async
