## 1. Relational Authority Principle

In compliance with **ADR-001**, the relational database (**PostgreSQL 16** in production, SQLite in test/development) is the **single authoritative system of record**.
- Every case, user, permission, evidence file metadata record, extracted claim, human arbitration review, audit event, and ledger anchor resides authoritatively in relational tables.
- All external systems (Neo4j graph projections, Redis caches, search indexes) are downstream analytical replicas and must remain 100% rebuildable from relational rows.
- **Timezone Invariance:** PostgreSQL connections and sessions are pinned to `UTC` (`SET TIME ZONE 'UTC'`), preventing HMAC signature invalidation caused by host timezone drift.

## 2. Core Relational Schema Entity Map

### 2.1 Governance & Access Models
- **`users`**: User identities, usernames, email, hashed passwords (PBKDF2), role (`INVESTIGATOR`, `EVIDENCE_OFFICER`, `REVIEWER`, `ANALYST`, `AUDITOR`, `ADMIN`), organization unit, active status, and `token_version` (incremented to revoke active JWT sessions).
- **`cases`**: Authorized investigation cases, title, description, case number, classification level, jurisdiction code, purpose specification, authority reference, status (`OPEN`, `ACTIVE`, `CLOSED`, `ARCHIVED`).
- **`case_assignments`**: Association linking users to cases with specific role scopes (`PRIMARY_INVESTIGATOR`, `CO_INVESTIGATOR`, `REVIEWER`, `AUDITOR`).
- **`permission_overrides`**: Time-bounded, supervisor-authorized temporary access elevations for cross-jurisdiction review.

### 2.2 Evidence & Extraction Models
- **`evidence`**: Uploaded evidence records, original filename, MIME type, byte size, file extension, storage key (S3/local path), SHA-256 hash, upload timestamp, quarantine status (`QUARANTINED`, `CLEAN`, `INFECTED`, `EXTRACTION_FAILED`, `PROCESSED`), scan engine version, and scanner timestamp.
- **`extraction_records`**: Provenance records detailing parsing method, tool version, and timestamp.
- **`claims`**: Granular extracted relationship and attribute assertions. Links source entity to target entity, relationship type (e.g. `CALLED`, `TRANSFERRED_MONEY`, `ASSOCIATED_WITH`, `MENTIONED_IN`), observed timestamp, confidence score (0.0 to 1.0), and fine-grained coordinate provenance (file ID, page, line, char offset, OCR bounding box, CSV row/col).

### 2.3 POLE+ Entity Models
- **`entities`**: Canonical POLE+ graph nodes:
  - `PERSON`: Suspects, witnesses, complainants.
  - `OBJECT`: Weapons, contraband, electronic devices.
  - `LOCATION`: Addresses, coordinates, crime scenes.
  - `EVENT`: Incidents, meetings, wire transfers, phone calls.
  - Additional types: `ORGANIZATION`, `VEHICLE`, `DOCUMENT`, `ACCOUNT`.
- **`match_candidates`**: Pairwise candidate matches generated by entity disambiguation engine. Stores source entity, candidate entity, deterministic match score, positive signals, and counter-signals.
- **`reviews`**: Human-in-the-loop arbitration decisions (`ACCEPTED`, `REJECTED`, `DEFERRED`), reviewing officer ID, timestamp, and mandatory written justification.

### 2.4 Audit & Ledger Models
- **`audit_events`**: Append-only audit entries capturing `event_id`, `case_id`, `user_id`, `action`, `client_ip`, `user_agent`, `timestamp_utc`, `details_json`, `previous_event_hash`, and `hmac_signature`.
- **`ledger_anchors`**: Cryptographic integrity anchors capturing `case_id`, `merkle_root`, `scheme` (`RFC6962` or legacy), `anchor_type` (`ETHEREUM_BESU`), `transaction_hash`, `block_number`, and `anchored_at`.

## 3. Database Migration Sequence (Alembic)

Database schema evolutions are managed strictly via Alembic revisions (`apps/api/migrations/versions/`):
1. `96ad003ca363`: Initial schema creation (cases, users, evidence, entities, claims, reviews).
2. `b9b204cf821f`: Added classification, jurisdiction, and purpose fields to cases and evidence.
3. `39486e0cbb1c`: Added authority reference metadata to cases and claims.
4. `5bcde1234567`: Added HMAC audit signature and previous hash chaining to `audit_events`.
5. `5bcde1234568`: Added unique index `uix_evidence_case_sha` preventing duplicate uploads of identical file bytes within a case.
6. `5bcde1234569`: Added `ledger_anchors` table and multi-case assignment support.
7. `5bcde1234570`: Added Merkle scheme specification (`RFC6962`) to `ledger_anchors`.
